# Security Routing

Use this reference to identify the smallest reasonable owner function or process category for open-source security questions. It is generic routing guidance, not an organization-specific policy, contact list, approval path, or escalation process.

Do not invent people, teams, email addresses, URLs, approvals, severity, escalation paths, or internal process names. Organization-specific routing is `Not configured` unless a verified organization-approved reference provides it.

## Route Categories

| Route | Generic owner function | When to use | What not to include | Organization-specific status |
| --- | --- | --- | --- | --- |
| Possible incident or active compromise | Incident response, security operations, or security response process | Suspected unauthorized access, active exploitation, compromised accounts, exposed sensitive data, production-impacting security control failure, ransomware, data loss, or credible active threat activity. | Secrets, credential values, suspected malware samples, exploit payloads, unnecessary personal data, customer data, or broad distribution of sensitive evidence. | Not configured |
| Suspected phishing | Phishing reporting, security operations, abuse handling, or incident response process | Suspicious email, message, login prompt, attachment, sender, social-engineering attempt, or credential-harvesting concern. | Do not forward outside the approved process, paste headers or content containing secrets, open attachments, follow links, or decode suspicious content. | Not configured |
| Suspected malware or suspicious URL | Incident response, malware intake, security operations, or abuse handling process | A file, attachment, URL, archive, executable, document, or artifact is described as malware, infected, suspicious, unsafe, malicious, or a bad URL. | Do not inspect, fetch, follow, open, extract, decode, summarize, upload, execute, or analyze the sample. | Not configured |
| Exposed secret | Incident response, secrets management, identity and access management, or service owner process | Credential, token, API key, private key, password, signing key, session token, or other secret may be exposed, committed, logged, shared, or sent to the wrong audience. | Do not paste the secret value, rely on deletion alone, share links in broad channels, or guess whether the secret was used. | Not configured |
| Vulnerability report | Vulnerability management, product security, security engineering, or maintainer triage process | A weakness, vulnerability report, security bug, dependency issue, misconfiguration, or responsible disclosure report needs triage and tracking, with no confirmed active compromise. | Exploit payloads beyond what the approved process requires, secrets, unnecessary sensitive data, or unsupported severity claims. | Not configured |
| Product or engineering bug | Product engineering, issue tracker, maintainer triage, or defect management process | A reproducible product defect, broken control, logic error, availability issue, or implementation bug may need engineering work and may or may not be security-relevant. | Final security severity, invented ownership, sensitive customer data, exploit instructions, or credentials. | Not configured |
| Architecture or infrastructure security question | Security architecture, infrastructure security, cloud security, platform security, or design review process | Design, threat model, cloud, network, identity, container, deployment, production infrastructure, or major control question needs review before or during implementation. | Secret values, production credentials, unrestricted diagrams with sensitive internals, or approval claims not backed by a verified process. | Not configured |
| Code or configuration security question | Secure code review, application security, maintainer review, or configuration review process | Source code, dependency, CI/CD, infrastructure-as-code, configuration, policy, build, or repository setting needs first-pass or focused security review. | Secrets, exploit payloads, malicious changes, bypass instructions, or claims that review equals approval. | Not configured |
| Privacy, legal, compliance, abuse, or safety concern | Privacy, legal, compliance, trust and safety, abuse, policy, or safety process | Personal data, regulated data, data handling, legal request, government inquiry, abuse report, spam, copyright, trademark, platform safety, or compliance concern needs non-engineering authority. | Legal conclusions, personal data beyond what the approved process requires, confidential data in broad channels, or invented approval paths. | Not configured |
| General security support | Security support, security engineering intake, maintainer support, or open-source project support process | The issue is security-related but not clearly an incident, phishing, malware, vulnerability, bug, architecture review, code review, or privacy/legal/compliance concern. | Secrets, suspected malware samples, broad sensitive evidence, or requests for unofficial escalation. | Not configured |

## Use Rules

- Apply hard stops before routing. Suspected malware, phishing, suspicious URLs, suspicious attachments, or malicious samples must stop without inspection, fetching, following, decoding, summarizing, or analysis.
- If a situation has possible active compromise, exposed secrets, ongoing exposure, user impact, customer impact, sensitive data, production impact, or exploitation indicators, route to the safest relevant response process category.
- If a vulnerability report also includes signs of active exploitation, treat it as a possible incident or active compromise.
- If an exposed secret is involved, treat it as a possible security event and preserve safe evidence while the approved owner handles rotation, revocation, and investigation.
- Use `Unknown` for missing facts, `Not assessed` for areas outside the review, and `Not configured` for missing organization-specific routes.
- Cite this reference separately from any public standards, local repository evidence, or verified organization references.
